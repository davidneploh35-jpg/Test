# Фото каталога -> 3:4 (1920x2560)

`photo_fix.py` берёт фотографии товаров и приводит их к 1920x2560.
**Ничего не обрезает**: фото, у которого соотношение примерно 3:4, дополняется по краям
до ровно 3:4 и масштабируется. Всё готовое складывается в одну папку.

## Установка (один раз)

```bash
pip install requests beautifulsoup4 pillow numpy
```

`mediapipe` нужен только для режима `--smart-crop` (см. ниже). Для обычной работы
он не требуется.

## Команды

```bash
# обработать уже скачанные фото, сайт не трогается
python photo_fix.py --local photos_ready/original --out gotovye --fix

# скачать с сайта и обработать
python photo_fix.py https://dr-arushanof.ru/index.php --crawl --max-pages 300 --fix

# только посмотреть, что есть на сайте: скачает и напишет отчёт, но не обработает
python photo_fix.py https://dr-arushanof.ru/index.php --crawl --max-pages 300
```

## Что происходит с фотографией

1. Соотношение сторон сверяется с 3:4. Отклонение до 10% считается «примерно 3:4»
   (меняется ключом `--ratio-tol`).
2. Подходящее фото дополняется по краю до ровно 3:4. Дополнение — продолжение
   крайних пикселей, обычно несколько пикселей, на однотонном фоне незаметно.
   **Из кадра ничего не пропадает.**
3. Результат масштабируется в 1920x2560 фильтром LANCZOS.
4. Если исходник был меньше 1920 по ширине, после увеличения применяется лёгкая
   нерезкая маска — она возвращает часть чёткости, потерянной при растягивании.
   Отключается ключом `--no-sharpen`.

Фото с другим соотношением (горизонтальные, 2:3 и прочие) не трогаются вовсе:
их копии складываются в `drugie_proportsii/`, чтобы решить по ним отдельно.

### Чего скрипт не может

Если исходник мельче 1920x2560, чёткость взять неоткуда — растянутое фото будет
мягче оригинала, и никакой фильтр этого не исправит. В отчёте у таких стоит
кратность увеличения (`x2.4`), а при увеличении больше чем вдвое — пометка, что
будет мылить. Смотри в отчёте строку «По размеру»: она сразу говорит, сколько
фотографий придётся тянуть вверх.

## Что получается

```
gotovye/
  007_dsc1234.jpg            готовые файлы, 1920x2560, JPEG качества 95
  011_img77.jpg
  drugie_proportsii/         не 3:4 — оставлены как есть
  report.csv                 построчно по каждому файлу
```

Колонки `report.csv`:

| Колонка | Что означает |
|---|---|
| `w`, `h` | Размер исходника |
| `status` | `ready`, `not_3x4`, `duplicate`, `too_small`, `skipped_existing` |
| `padded` | Сколько процентов площади — дополненный край |
| `upscaled` | Во сколько раз пришлось увеличить (`x2.4`); пусто, если увеличения не было |
| `note` | Пометки |

В конце прогона печатаются две сводки: распределение пропорций исходников и
сколько фотографий мельче 1920 по ширине.

## Ключи

| Ключ | Зачем |
|---|---|
| `--local ПАПКА` | Работать с папкой на диске вместо сайта |
| `--redo` | Переделать даже то, что уже лежит в папке результата |
| `--ratio-tol 0.10` | Какое отклонение от 3:4 считать «примерно 3:4» |
| `--no-sharpen` | Не подрезкостривать после увеличения |
| `--quality 95` | Качество JPEG |
| `--jobs 8` | Сколько картинок качать одновременно |
| `--min-side 400` | Порог отсева иконок и логотипов |
| `--smart-crop` | Старое поведение: кадрировать по категориям товара |

### Про `--smart-crop`

Режим, который кадрирует по типу изделия: костюмы в полный рост, брюки по пояс,
блузки чуть ниже пояса. Он **режет** фотографию и потом растягивает вырезанный
кусок до 1920x2560, поэтому у мелких исходников результат заметно мылит. Требует
`pip install mediapipe`. По умолчанию выключен.
